# FleetSync Web — guide for Claude Code

FleetSync is a fleet management system (team devSync, IN2901 Software Development Project).
This folder is the **desktop web app** for four roles: Customer, Operational Coordinator,
Fleet Administrator and Fleet Owner. Drivers and Mechanics use `apps/mobile` instead.

## The design is the spec

All screens are finished in Figma: **https://www.figma.com/design/kVIYQZ1EidykzANXtuGpJx/UI-design**

- Page **Screens**: every screen, one frame each, named `<Role> — <Area> / <View>`.
- Page **Style Guide**, frame *FMS — Design System v2*: colour tokens, type scale, components
  (Button, Status Badge, Input, Select, Tab, KPI Card, Banner, Empty state, Top bar),
  sidebars per role, dashboard patterns and empty/error states.
- **`docs/design/figma-screens.md`** lists every screen with its direct Figma link. Look up the
  screen there when you are asked to build one.

When building a screen:
1. Read the frame with the Figma connector (`get_design_context` + `get_screenshot`) before writing code.
2. Match layout, spacing, text and states to the frame. Translate Figma colours to the tokens
   below; never paste raw hex values into components.
3. Reuse components in `src/components/ui` and `src/components/shared` before making new ones.
   If a Figma component (e.g. Status Badge, KPI Card) has no code version yet, create it in
   `components/shared` so other screens can use it.
4. Some screens have variant frames (e.g. *Submitted orders / Needs quotation*, *Quoted*…).
   These are states or tabs of one page, not separate pages.

## Stack (agreed by the team — do not swap)

- React 19 + TypeScript (strict) + Vite
- Routing: **React Router**
- HTTP: **axios** through one shared client (`src/services/apiClient.ts`)
- Styling: **Tailwind CSS v4** (`@tailwindcss/vite`) + **shadcn/ui** (components copied into `src/components/ui/`)
- Icons: `lucide-react` (shadcn default)
- Imports use the `@/` alias for `src/` (set in `tsconfig.json`, `tsconfig.app.json` and `vite.config.ts`)

Run everything from the repo root:

- `npm run dev:web` — dev server
- `npm run build:web` — type-check and build (CI runs this)
- `npm run lint --workspace=apps/web` — ESLint (CI runs this)

## Folder structure (feature-based)

```
src/
├── app/
│   ├── router.tsx          all routes, grouped per role (/coordinator/*, /admin/*, /customer/*, /owner/*, /auth/*)
│   ├── providers.tsx       app-wide providers
│   └── layouts/            AuthLayout + one layout per role (sidebar + top bar), e.g. CoordinatorLayout.tsx
├── features/               one folder per module
│   └── <feature>/
│       ├── pages/          route-level components (XxxPage.tsx)
│       ├── components/     components used only by this feature
│       ├── hooks/          hooks used only by this feature (useXxx.ts)
│       ├── services/       API calls for this feature (xxxApi.ts) — uses apiClient
│       ├── mocks/          mock data used until the backend endpoint exists
│       └── types.ts        this feature's TypeScript types
├── components/
│   ├── ui/                 shadcn/ui components (generated by the shadcn CLI — edit only to restyle)
│   └── shared/             FleetSync pieces from the Figma design system: StatusBadge, KpiCard, PageHeader, EmptyState, DataTable…
├── contexts/               only truly global state (e.g. AuthContext)
├── hooks/                  hooks shared by two or more features
├── services/apiClient.ts   the one axios instance (base URL from VITE_API_BASE_URL, auth header, error handling)
├── lib/utils.ts            shadcn `cn()` helper and small utilities (formatLKR, formatDate)
├── index.css               Tailwind entry + design tokens (see below)
└── main.tsx
```

Feature folders map to the Figma areas: `auth`, `coordinator-dashboard`, `orders`, `quotations`,
`trips`, `availability`, `reports`, `chat`, `mail`, `notifications`, `profile`, `admin-users`,
`applications`, `change-approvals`, `vehicles`, `reference-data`, `audit-log`, `customer-orders`,
`payments`, `owner-dashboard`, `fleet-analysis`. Create a folder only when work on it starts.

Rules:
- Code lives inside its feature. Move it to `components/shared`, `hooks/` or `services/` only when a **second** feature needs it.
- Features never import from another feature's internal folders. If two features need the same thing, move it to shared.
- Pages stay thin: fetch data with a hook, lay out components. No axios calls inside components.
- One component per file; PascalCase file names for components, camelCase for hooks and services.

## Data fetching

- Every API call goes through `apiClient` from a feature's `services/` file. Never call `axios` directly elsewhere.
- Until a backend endpoint exists, the service returns data from the feature's `mocks/` folder behind the same
  async function signature, so swapping to the real API only changes the service file.
- Handle loading, empty and error states on every page (the Style Guide has patterns for each).

and `@fontsource/jetbrains-mono`).

|---|---|---|

| Page title | 28 / Bold | Maintenance schedule |

| Card title | 16 / Semi Bold | Vehicle details |

## Component and content rules

- **Status badges**: soft tinted background with the label in the strong colour, no dot. One colour per meaning:
  neutral = inactive/draft/off duty, pending = pending/due soon, accent = assigned/quoted/scheduled,
  info = on trip/in progress, success = active/completed/paid, danger = overdue/failed/suspended/cancelled.
  Build one `StatusBadge` component and map each domain status to a tone in one place.
- Never strike through or draw lines across field values. Old values show in grey with a "Current" or "Before" label.
- Tables: small buttons in the Actions column (e.g. "View") plus a ⋯ menu for the rest.
- Desktop frames are 1440px wide; layouts should also work down to about 1024px.
- Mock data is Sri Lankan and consistent across screens: same people, plates like `WP CAB-4521`,
  IDs `ORD-`, `TRP-`, `APP-`, amounts in LKR. Copy names and values from the Figma frames.

## Scope rules

- The use case diagram is the source of truth. Do not add features that are not on it; flag them instead.
- **No GPS, live map, ETA or IoT tracking anywhere.**
- Only the Fleet Administrator changes user roles. Users cannot request a role.
- The Operational Coordinator matches a vehicle, a driver and a mechanic to each trip. No screen shows a fixed vehicle for a driver.
- Fleet Owner pages are read-only.
- Payments are card-only through PayHere. Cancelling a trip that is Assigned or In Progress triggers an automatic full refund.

## Git

- Short-lived feature branches (e.g. `feature/web-coordinator-dashboard`), pull request into `main`, at least one peer review.
- Conventional commit messages (`feat:`, `fix:`, `chore:`, `docs:`).
- CI must pass: `build:web` and lint.
